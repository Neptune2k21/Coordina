The root `.env` file configures Docker, PostgreSQL, and API authentication.
Start from `.env.example` for local development.

```dotenv
POSTGRES_USER=coordina
POSTGRES_PASSWORD=change-me
POSTGRES_DB=coordina
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
ADMINER_PORT=8080
ASPNETCORE_ENVIRONMENT=Development

Auth__Issuer=Coordina.Api
Auth__Audience=Coordina.Web
Auth__SigningKey=change-me-to-a-secure-random-secret-with-at-least-32-characters
Auth__AccessTokenMinutes=60
```

## Allowed web origins

Browsers only let the web app call the API, and send the refresh cookie, from
an origin listed in `Cors:AllowedOrigins`. Set one environment variable per
origin:

```dotenv
Cors__AllowedOrigins__0=https://app.example.com
Cors__AllowedOrigins__1=https://beta.example.com
```

- In `Development`, `src/api/appsettings.Development.json` already allows the
  local Vite ports (`5173` for `make web`, `5174` for the end-to-end tests), on
  both `localhost` and `127.0.0.1`. A variable replaces the default at the
  same index, so `Cors__AllowedOrigins__0` alone replaces
  `http://localhost:5173` and keeps the other three.
- In any other environment the API refuses to start when the list is empty,
  instead of rejecting every browser request.
- Each value is an origin, `scheme://host[:port]`, as the browser sends it:
  `https://app.example.com/` (trailing slash) or a path stops the API at
  startup, since it could never match.

## Sign-in rate limit

`POST /auth/login` and `POST /auth/register` share a limit per client IP. Past
it, the API answers `429 Too Many Requests` with a `Retry-After` header, and the
sign-in form shows how long to wait.

```dotenv
RateLimiting__Auth__PermitLimit=10
RateLimiting__Auth__WindowSeconds=60
```

- The defaults are 10 attempts per 60 seconds.
- `Development` allows 100 (`src/api/appsettings.Development.json`), since the
  end-to-end tests sign up and sign in many times from `127.0.0.1`.
- The `Testing` environment turns the limit off, unless a test sets one, so
  API tests do not depend on each other.
- The limit uses the connection's address. Behind a reverse proxy, configure
  forwarded headers for that proxy first; otherwise every client shares the
  proxy's address and its limit.

## Web app variables

The web app also supports these Vite variables:

```dotenv
VITE_API_URL=http://localhost:5050
VITE_DOCS_URL=http://localhost:3000
```

`VITE_DOCS_URL` should point to Mintlify. If it is not set, the web app falls
back to the production docs domain.

## Environment configuration

The local `.env` file follows this shape:

```dotenv
POSTGRES_USER=coordina
POSTGRES_PASSWORD=change-me
POSTGRES_DB=coordina
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
ADMINER_PORT=8080
ASPNETCORE_ENVIRONMENT=Development

Auth__Issuer=Coordina.Api
Auth__Audience=Coordina.Web
Auth__SigningKey=change-me-to-a-secure-random-secret-with-at-least-32-characters
Auth__AccessTokenMinutes=60
```

The checked-in example is for local development only. Use a unique signing key and managed secrets outside local environments.
