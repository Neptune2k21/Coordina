---
title: "Workspaces"
description: "Workspace tenancy, membership, invitations, and server-side access rules."
---

Workspaces are Coordina's tenant boundary. Projects, boards, tasks, and future
collaboration modules should scope data through the active workspace ID.

## API surface

```http
GET    /workspaces
POST   /workspaces              { "name": "Product Team" }
GET    /workspaces/{workspaceId}
POST   /workspaces/join         { "inviteCode": "A1B2C3D4E5F6" }
POST   /workspaces/{workspaceId}/invites
GET    /workspaces/{workspaceId}/members
PATCH  /workspaces/{workspaceId}/members/{memberUserId}  { "role": "OWNER" }
POST   /workspaces/{workspaceId}/leave
DELETE /workspaces/{workspaceId}/members/{memberUserId}
DELETE /workspaces/{workspaceId}
```

## Security model

- List queries are filtered by current user membership.
- Details return `404` for non-members.
- Join requires a valid one-time invitation code.
- Workspace creation auto-creates an `OWNER` membership.
- Invite creation requires workspace ownership.
- Role changes and member removal require workspace ownership. An owner is
  removed by making them a `MEMBER` first.
- Workspace deletion requires workspace ownership.
- Frontend state is never trusted for authorization.

## Roles and ownership

A workspace always keeps at least one `OWNER`:

- Demoting the last owner, or the last owner leaving, returns `409` with
  the reason. When nobody else is left, delete the workspace instead.
- To hand a workspace over, make another member `OWNER`, then step down
  (`PATCH` your own membership to `MEMBER`) or leave.
- Membership changes for one workspace run one at a time, under a lock that
  the owner check is part of. Two owners demoting each other at the same
  moment leave one owner: the second request finds it is no longer allowed
  and gets `403`.

## Leaving or being removed

`POST /workspaces/{workspaceId}/leave` lets any member leave. Leaving and being
removed have the same effect, in one transaction:

| Data | What happens |
| --- | --- |
| Card assignments in the workspace | Dropped |
| Projects the member owned | Go to the owner who removed them, or, when they left, to the longest-standing owner |
| Comments and completed work | Kept, with their author |

Modules higher in the dependency chain take part by implementing
`IWorkspaceDepartureHandler`, which the workspaces module calls without
referencing them.
